01 · The idea

Don’t ask only “what matters?” Ask “what is the model missing?”

A feature can be unimportant by itself and still become decisive when paired with another feature. A global average can also hide a small group where the model repeatedly fails.

Known signal

Feature importance

“Transaction amount is useful.”

Helpful for understanding the current model—but it mostly describes the patterns the model has already learned.

New hypothesis

Residual investigation

“A normal-looking amount becomes risky when it is unusual for this seller.”

Look for signals associated with errors or under-prediction, not just signals associated with fraud overall.

Proof required

Out-of-time test

“Does the pattern still help next month?”

A pattern is a lead—not a discovery—until it survives replication, leakage checks, and future-period evaluation.

Important: this is a discovery framework, not a promise that every unusual pattern is predictive or causal. The data and validation process must decide.

06 · Detector toolbox

Six ways to search for hidden clues

No single scanner finds everything. Each one looks for a different kind of suspicious behaviour.

Clues that appear together

Two details may look harmless separately but become suspicious when they happen together. Technical tools: interaction screening and SHAP interaction values.

Find combinations

Changes from normal behaviour

Compare someone’s recent activity with their own usual pattern—for example, a payment 8× larger than normal.

Find change

Small groups with a shared clue

Find a group where the same simple conditions repeat, such as new sellers with an unusual burst of payments.

Find slices

Hidden extremes

Two groups can have the same average while one contains far more extreme values. Look beyond averages.

Find shape shifts

Unusual pockets

Group similar transactions together and inspect pockets that behave differently from the rest.

Find unusual pockets

Where the model gets it wrong

Compare its predictions with what really happened. Focus on groups where it repeatedly expected less fraud than occurred.

Find model blind spots
Practical note: discovery at scale creates false positives. Use false-discovery-rate control, replication, minimum support thresholds, stability checks, and a final out-of-time ablation.
07 · From clue to improvement

What do we do when a clue looks real?

A useful discovery should become something the model or fraud team can actually use. Here is the simple path.

01 TURN IT INTO A SIGNAL

Describe the behaviour

Example: “This payment is much larger than this seller’s usual payment.”

Recent amount ÷ usual amount
02 CHECK IT IS REAL

Look again later

Check a different time period. If the clue disappears, it may have been a coincidence.

Does it happen again?
03 SEE IF IT HELPS

Test the model fairly

Compare the old model with the improved version on future transactions it has never seen.

Did we catch more fraud?
💡

The rule of the game: a clue is not automatically a good feature. Keep it only if it repeats and helps the model make better decisions.

08 · The big picture

How the detective finds a real blind spot

The system searches for clues, tries to disprove them, and keeps only the ones that genuinely help.

1
Find something unusual

Look for a combination or group the model may be overlooking.

2
Compare with what the model expected

Check whether the model consistently guessed too low for this group.

3
Try to prove the clue wrong

Check that it is not a tiny sample, a data mistake, or a one-time coincidence.

4
Test on future transactions

Keep the clue only if it improves results on data the model has not seen.

Where AI helps

AI is the guide, not the judge

An AI assistant can suggest what to investigate next and explain the result in plain English. Trusted code calculates the numbers and checks the evidence.

Goal: fewer false alarms, clearer explanations, and more fraud caught within the same review capacity.
